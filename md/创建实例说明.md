# 创建实例说明

本文档说明在某个场景下「创建实例」的接口、数据流、父子关系与 Neo4j 中的存储方式。

---

## 一、流程概览

1. 前端调用 **POST /scenes/{scene_id}/instances**，传入场景 ID、实例名称、父节点 uid（可选）及资产/变换/绑定等。
2. 后端校验场景存在、若传了 `parent_uid` 则校验父节点存在。
3. 用 **InstanceCreate** 构建 **Instance** 节点，设置 name、asset_id、transform、properties 等，调用 **inst.save()** 写入 Neo4j（生成实例 uid）。
4. 建立父子关系：有父则 **parent.children.connect(inst)**（父 -[:PARENT_OF]-> 新实例）；无父则挂到场景根节点 **root.children.connect(inst)**。
5. 建立场景引用 **inst.scenes.connect(scene)**（Scene -[:HAS_INSTANCE]-> Instance）。
6. 返回新实例的 **uid**、**name**。

## 三、路由内逻辑（逐行）

```python
# 1. 根据 scene_id 查场景，不存在则 404
scene = Scene.nodes.get_or_none(uid=scene_id)
if not scene:
    raise HTTPException(404, "场景不存在")

# 2. 若传了 parent_uid，查父节点，不存在则 404
parent = None
if data.parent_uid:
    parent = Instance.nodes.get_or_none(uid=data.parent_uid)
    if not parent:
        raise HTTPException(404, "父节点不存在")

# 3. 创建 Instance 节点（内存），并设置字段
inst = Instance(name=data.name)
if data.asset_id:
    inst.asset_id = data.asset_id
if data.asset_type:
    inst.asset_type = data.asset_type
if data.transform:
    inst.transform = data.transform
# ... properties, materials, iot_binds, video_binds, file_binds 同理

# 4. 保存到 Neo4j（此时生成 inst.uid）
inst.save()

# 5. 建立父子关系（PARENT_OF）
if parent:
    parent.children.connect(inst)   # 父 -[:PARENT_OF]-> 新实例
else:
    root = scene.root.single()      # 场景的根 Instance
    if root:
        root.children.connect(inst) # 根 -[:PARENT_OF]-> 新实例

# 6. 建立场景引用（HAS_INSTANCE）
inst.scenes.connect(scene)          # Scene -[:HAS_INSTANCE]-> Instance
     详细关系定义在 创建场景说明.md里

return {"uid": inst.uid, "name": inst.name}
```

- **inst.uid**：在 **inst.save()** 时由 neomodel 的 **UniqueIdProperty** 自动生成，与「创建场景」里 Scene.uid 同理，写入 Neo4j。

## 四、Instance 模型与关系（Neo4j）

**文件**：`app/models/scene.py`（约 88–114 行）
        创建场景里「实例」在系统里的具体内容，定义实例的 样子
        class Instance(StructuredNode):
            """场景中的实例化节点，可嵌套"""
            uid        = UniqueIdProperty()
            name       = StringProperty()
            
            # 资产信息
            asset_id   = StringProperty(index=True)                # 资产ID
            asset_type = StringProperty(default="model")           # 资产类型：model, 3dtiles, gis_layer 等

            transform  = JSONProperty(default=lambda: {           # 位置、旋转、缩放的3×3矩阵
                'location': [1,0,0],
                'rotation': [0,0,0],
                'scale': [1,1,1]
            })
            properties = JSONProperty(default=dict)
            materials  = JSONProperty(default=list)

            # 绑定属性数组
            iot_binds  = JSONProperty(default=list)               # IoTBinding对象数组，支持复杂绑定配置
            video_binds = JSONProperty(default=list)              # Mongo 文档 _id 数组
            file_binds  = JSONProperty(default=list)              # Mongo 文档 _id 数组

            # 关系
            parent     = RelationshipFrom('Instance', 'PARENT_OF', model=ParentRel)
            children   = RelationshipTo('Instance', 'PARENT_OF', model=ParentRel)

            # 场景引用
            scenes     = RelationshipFrom(Scene, 'HAS_INSTANCE')


### 节点属性（存于 Neo4j 的 Instance 节点）

| 属性 | 类型 | 说明 |
|------|------|------|
| uid | 自动生成 | UniqueIdProperty，实例唯一标识 |
| name | str | 实例名称 |
| asset_id | str | 资产 ID |
| asset_type | str | 默认 "model" |
| transform | JSON | location / rotation / scale 等 |
| properties | JSON | 扩展属性（若引用 Mongo 的 instance_properties，会存 _id） |
| materials | JSON | 材质列表 |
| iot_binds / video_binds / file_binds | JSON | 各类绑定配置 |

### 关系（均在 Neo4j 中）

| 关系 | 方向 | 说明 |
|------|------|------|
| **PARENT_OF** | 父 Instance -[:PARENT_OF]-> 子 Instance | 实例树层级，用 `parent` / `children`（ParentRel） |
| **HAS_INSTANCE** | Scene -[:HAS_INSTANCE]-> Instance | 场景「拥有」该实例，用 Instance 的 `scenes` RelationshipFrom |

创建实例时会发生：

- 新建一个 **Instance** 节点（`inst.save()`）。
- 一条 **PARENT_OF**：要么从 `parent` 连到 `inst`，要么从场景的 **root** 连到 `inst`。
- 一条 **HAS_INSTANCE**：从该 **Scene** 连到 `inst`。

## 五、与「创建场景」的对比

## 八、小结

- **创建实例**：POST /scenes/{scene_id}/instances，Body 用 **InstanceCreate**（name、asset_id 必填，parent_uid 可选）。
- **保存**：`inst.save()` 把 Instance 写入 Neo4j并生成 **inst.uid**。
- **挂树**：有 `parent_uid` 则 `parent.children.connect(inst)`；否则 `scene.root.single()` 得到根，再 `root.children.connect(inst)`。
- **归属场景**：`inst.scenes.connect(scene)`，形成 Scene -[:HAS_INSTANCE]-> Instance。
- 实例树结构完全由 **PARENT_OF** 关系在 Neo4j 中维护。

============================================================
用更直白的话再说一遍实例是怎么被创建出来的：

打个比方：场景像一个「文件夹」，实例就是文件夹里的「文件」。创建实例，就是在某个文件夹里新建一个文件，并且要记清楚：这个文件放在哪一层（是直接放在根目录，还是放在某个子文件夹下），以及它属于哪个场景文件夹。

第一步：用户在前端填表、点创建

用户在页面上选一个场景，填实例名字、选要用的模型（资产），还可以选父节点、位置、旋转、缩放等。点「创建实例」后，浏览器会把这些信息发给后端。

第二步：后端先做检查

后端收到请求后：

先看用户有没有登录，没登录就不让创建。
再根据传过来的「场景 id」去数据库里找这个场景。找不到就提示「场景不存在」。
如果用户选了「父实例」，再根据「父实例 id」去数据库里找这个父节点。找不到就提示「父节点不存在」。
只有这些都通过了，才会继续往下做。

第三步：在内存里“捏”出一个实例对象

后端用请求里传来的数据，按照系统里定义好的「实例长什么样」（Instance 模型），在内存里先造出一个实例对象，可以叫它 inst。
给 inst 填上名字、资产 id、位置、旋转、缩放、属性、绑定信息等——请求里传了什么就填什么。
这时候 inst 还只存在于程序内存里，数据库里还没有它。

第四步：把实例写进 Neo4j 数据库

接着执行 inst.save()。
程序会把这个实例真正存进 Neo4j，变成图里的一个「实例节点」，并且自动生成一个唯一的 uid。
到这一步，数据库里已经有一条新实例了，但还没有说明「它挂在谁下面、属于哪个场景」。

第五步：把实例“挂”到树上去（父子关系）

接下来要决定：这个新实例是挂在谁下面？

如果用户选了父实例：就在数据库里建一条「父实例 → 新实例」的连线（PARENT_OF），表示新实例是那个父节点的子节点。
如果用户没选父实例：就找到这个场景的「根节点」，建一条「根节点 → 新实例」的连线，表示新实例直接挂在场景根下。
这样，新实例在「实例树」里就有了明确位置，不会飘着。

第六步：标记这个实例属于哪个场景

再建一条「场景 → 新实例」的连线（HAS_INSTANCE），表示：这个实例属于当前这个场景。
以后按场景查「这个场景下有哪些实例」时，就靠这条关系来查。

第七步：把结果告诉前端

后端把新实例的 uid 和 name 返回给前端。
前端用这个 uid 去加载 3D 模型、在场景树里显示这个实例、做编辑等。

用一句话总结：
用户填表点创建 → 后端先检查场景和父节点是否存在 → 在内存里按「实例模型」造出一个 inst 并填好数据 → 用 inst.save() 把实例存进 Neo4j 并得到 uid → 再在 Neo4j 里连两条线：一条是「挂到父节点或根节点下」（父子），一条是「属于这个场景」→ 最后把 uid 和 name 返回给前端。
整件事就是：先按模板造出实例，再存进库、挂好关系、告诉前端。
