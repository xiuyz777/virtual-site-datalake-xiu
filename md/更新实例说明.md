# 更新实例说明

本文档说明「更新实例」的接口、数据流、单个更新与批量更新的区别，以及 Neo4j 中的更新方式。

---

## 一、流程概览

### 单个更新实例
1. 前端调用 **PUT /instances/{instance_id}**，传入实例 uid 和要更新的字段（InstanceUpdate）。
2. 后端根据 `instance_id` 查实例，不存在则 404。
3. 按请求体字段逐个判断并赋值（只更新传入的字段）。
4. `inst.save()` 将修改写回 Neo4j（neomodel 生成 MERGE/UPDATE 的 Cypher）。
5. 返回更新后的 `uid`、`name`。

### 批量更新实例
1. 前端调用 **POST /instances/batch-update**，传入多个实例的更新项（BatchInstanceUpdate）。
2. 后端在 **Neo4j 事务**中遍历每个更新项。
3. 对每个实例：查实例 → 更新 transform → save() → 记录成功/失败。
4. 返回汇总结果（成功数、失败数、详细列表）。

    id: str  # 实例的uid

## 四、路由内逻辑（逐行）

### 单个更新（scene.py 273–295）

```python
# 1. 根据 instance_id 查实例，不存在则 404
inst = Instance.nodes.get_or_none(uid=instance_id)
if not inst:
    raise HTTPException(404, "实例不存在")

# 2. 按请求体字段逐个判断并赋值（只更新传入的字段）
if data.name:
    inst.name = data.name
if data.asset_id:
    inst.asset_id = data.asset_id
if data.asset_type:
    inst.asset_type = data.asset_type
if data.transform:
    inst.transform = data.transform
if data.properties:
    inst.properties = data.properties
if data.materials:
    inst.materials = data.materials
if data.iot_binds:
    inst.iot_binds = data.iot_binds
if data.video_binds:
    inst.video_binds = data.video_binds
if data.file_binds:
    inst.file_binds = data.file_binds

# 3. 保存到 Neo4j（neomodel 会生成 MERGE/UPDATE 的 Cypher）
inst.save()

# 4. 返回更新后的 uid 和 name
return {"uid": inst.uid, "name": inst.name}
```

**关键点**：
- **部分更新**：每个字段用 `if data.xxx:` 判断，只更新传入的字段。
- **inst.save()**：neomodel 会生成 MERGE/UPDATE 的 Cypher，只更新已修改的属性。

### 批量更新（scene.py 303–328）

```python
# 1. 初始化结果字典（success / failed）
results = {"success": [], "failed": []}

# 2. 使用 Neo4j 事务处理批量更新，确保原子性
with neo_db.transaction:
    for update in data.updates:
        try:
            # 3. 查实例，不存在则记录失败并 continue
            inst = Instance.nodes.get_or_none(uid=update.id)
            if not inst:
                results["failed"].append({"id": update.id, "reason": "实例不存在"})
                continue
            
            # 4. 只更新 transform 属性
            if update.transform:
                inst.transform = update.transform
                inst.save()
                results["success"].append(update.id)
            else:
                results["failed"].append({"id": update.id, "reason": "没有提供transform属性"})
        except Exception as e:
            # 5. 异常捕获并记录失败
            results["failed"].append({"id": update.id, "reason": str(e)})

# 6. 返回汇总结果
return {
    "message": f"批量更新完成，成功: {len(results['success'])}，失败: {len(results['failed'])}",
    "results": results
}
```

**关键点**：
- **事务**：`with neo_db.transaction:` 保证批量操作的原子性。
- **部分失败不影响已成功的更新**：事务内每个实例独立处理，一个失败不影响其他。
- **只支持 transform**：批量更新目前只支持更新 transform 属性。

## 六、关键点说明

### 1. 部分更新（Partial Update）

- **原理**：更新接口只改传入的字段，未传字段保持不变。
- **实现方式**：每个字段用 `if data.xxx:` 判断，只更新传入的字段。
- **优势**：前端可以只传要改的字段，不需要传完整对象。

### 2. save() 的行为

- **neomodel 的 save()**：会生成 MERGE/UPDATE 的 Cypher，只更新已修改的属性。
- **未修改的属性**：不会触发写操作，保持原值。

### 3. 批量更新的事务

- **`with neo_db.transaction:`**：保证批量操作的原子性。
- **部分失败不影响已成功的更新**：事务内每个实例独立处理，一个失败不影响其他。
- **用途**：主要用于同时移动多个实例（批量更新 transform）。

### 4. 批量更新的限制

- **只支持 transform**：批量更新目前只支持更新 transform，不支持其他字段（如 name、asset_id 等）。
- **原因**：批量更新主要用于同时移动多个实例，transform 是最常用的场景。

## 七、数据存储

| 操作 | 存储位置 | 说明 |
|------|----------|------|
| 更新 Instance 节点属性 | **Neo4j** | `inst.save()` 更新 Instance 节点的属性值（name、asset_id、transform、properties 等） |
| 关系 | **不变** | 不修改 PARENT_OF、HAS_INSTANCE 关系 |

**注意**：更新实例**不修改关系**，只更新节点属性。如需修改父子关系，需要使用其他接口（如更新实例嵌套关系的 API）。

## 九、小结

- **单个更新实例**：PUT /instances/{instance_id}，Body 用 **InstanceUpdate**（所有字段可选），只更新传入的字段，`inst.save()` 写回 Neo4j。
- **批量更新实例**：POST /instances/batch-update，Body 用 **BatchInstanceUpdate**（多个 InstanceBatchItem），在 **Neo4j 事务**中批量更新 transform，返回成功/失败汇总。
- **部分更新**：更新接口只改传入的字段，未传字段保持不变。
- **不修改关系**：更新实例不修改 PARENT_OF、HAS_INSTANCE 关系，只更新节点属性。
- **批量限制**：批量更新目前只支持更新 transform，不支持其他字段。
