# 选择目标属性详细说明

## 概述

「选择目标属性」功能是 IoT 绑定配置中的核心功能之一，允许用户通过可视化界面选择实例的属性、模型的节点或材质作为 IoT 数据绑定的目标路径。该功能避免了手动输入路径字符串，提供了直观的树形结构选择界面。

1. 功能是做什么
选择目标属性 = 在配置 IoT 绑定时，用可视化树选「数据要写到实例的哪里」，得到 target 路径，避免手写字符串。
和「预览数据」对应：预览数据选的是 source（数据从哪来），选择属性选的是 target（数据写到哪）。

3. **材质属性**（`materials`）：3D 模型的材质属性

#### 1.2 树结构构建
**函数**：`buildPropertyTree()` (第 1228-1267 行)
    web/src/components/DataPathHelper.tsx
    在该文件里它被用于把实例属性数据转成树结构，并在约第 2087 行作为 treeData={buildPropertyTree(instanceProperties, '', '0', true)} 传给「选择目标属性」里的实例属性树组件。

**调用方式**：
```typescript
buildPropertyTree(instanceProperties, '', '0', true)
```

**构建逻辑**：
1. **根级别路径**：使用 `iotBindingAPI.buildTargetPath(TargetType.INSTANCE, key)` 构建
   - 格式：`instance.{key}`
   - 例如：`instance.asset`、`instance.instance`、`instance.bindings`

2. **嵌套路径**：对于对象类型的值，递归构建子节点
   - 格式：`instance.{parentKey}.{childKey}`
   - 例如：`instance.instance.properties.temperature`

3. **路径示例**：
   ```
   instance
   ├── asset
   │   ├── asset_id
   │   └── asset_type
   ├── instance
   │   ├── uid
   │   ├── name
   │   ├── transform
   │   │   ├── location
   │   │   ├── rotation
   │   │   └── scale
   │   ├── materials
   │   └── properties
   │       ├── temperature
   │       └── humidity
   └── bindings
       ├── iot_binds
       ├── file_binds
       └── video_binds
   ```

**代码实现**：
```typescript
const buildPropertyTree = (data: any, prefix = '', parentKey = '0', isRoot = false): ExtendedDataNode[] => {
  if (!data || typeof data !== 'object') {
    return [];
  }

  return Object.keys(data).map((key, index) => {
    const nodeKey = `${parentKey}-${index}`;
    // 在根级别使用instance前缀
    const currentPath = isRoot 
      ? iotBindingAPI.buildTargetPath(TargetType.INSTANCE, key)
      : (prefix ? `${prefix}.${key}` : key);
    const value = data[key];
    
    const node: ExtendedDataNode = {
      key: nodeKey,
      title: <span>...</span>,
      data: { path: currentPath, value, type: typeof value }
    };

    // 递归处理嵌套对象
    if (typeof value === 'object' && value !== null && !Array.isArray(value)) {
      node.children = buildPropertyTree(value, currentPath, nodeKey, false);
    }

    return node;
  });
};
```

#### 1.3 路径格式

**TargetType 定义**：`web/src/services/iotBindingApi.ts` (第 46-50 行)
```typescript
export enum TargetType {
  INSTANCE = "instance",
  NODE = "node", 
  MATERIAL = "material"
}
```
        TargetType 表示 IoT 绑定的“目标类型”：数据要写到哪里。
        在「选择目标属性」里对应三种目标：
        枚举值	含义	对应 UI	路径示例
        INSTANCE ("instance")	实例属性	「实例属性」tab	instance.instance.transform.location、instance.bindings.iot_binds 等，来自 Neo4j Instance 的字段
        NODE ("node")	节点属性	「节点属性」tab	node.0.translation、node.1.scale 等，来自模型节点/骨架（如 asset_metadata 或 Cesium 节点）
        MATERIAL ("material")	材质属性	「材质属性」tab	material.0.baseColorFactor 等，来自 Cesium 模型的材质
        一条绑定会选一个 数据源路径（source）和一个 目标路径（target）。TargetType 用来区分这条绑定的 target 是「实例级」「节点级」还是「材质级」，从而决定用哪套树（buildPropertyTree / buildNodeTree / buildMaterialTree）和存到哪类配置里（例如 iot_binds 里会带 targetType）。

**buildTargetPath 函数**：`web/src/services/iotBindingApi.ts` (第 305-311 行)
```typescript
buildTargetPath: (type: TargetType, id: string, property?: string): string => {
  let path = `${type}.${id}`;
  if (property) {
    path += `.${property}`;
  }
  return path;
}
```
      buildTargetPath 用来拼出「目标属性」的路径字符串，格式是：{类型}.{id} 或 {类型}.{id}.{属性}。
      type：目标类型，即 TargetType（instance / node / material）。
      id：该类型下的标识。
      实例：通常是 "instance"、"asset"、"bindings" 等分组/字段名。
      节点：节点索引，如 "0"、"1"。
      材质：材质索引，如 "0"。
      property（可选）：在 id 下的具体属性名，可多级用 . 连（这里只拼一段，多级一般由上层再拼）。

**实例属性路径格式**：
- 根级别：`instance.{propertyName}`
- 嵌套属性：`instance.{propertyName}.{nestedKey}`
- 深层嵌套：`instance.{propertyName}.{key1}.{key2}`

**示例**：
- `instance.instance.properties.temperature`
- `instance.instance.transform.location`
- `instance.bindings.iot_binds`

#### 2.2 树结构构建

**函数**：`buildNodeTree()` (第 1270-1359 行)

**构建逻辑**：
1. **节点路径**：`node.{nodeId}.{property}`
   - `nodeId` 是从 `node.id` 中去掉 `node_` 前缀得到的
   - 例如：`node.node_1` → `node.1`

2. **节点属性**：每个节点包含三个固定属性作为子节点
   - `translation`：位置 `[x, y, z]`
   - `rotation`：旋转 `[x, y, z, w]`
   - `scale`：缩放 `[x, y, z]`

3. **递归处理**：如果节点有子节点，递归构建子节点树

**路径示例**：
```
node
├── 1
│   ├── translation
│   ├── rotation
│   └── scale
└── 2
    ├── translation
    ├── rotation
    └── scale
```

**代码实现**：
```typescript
const buildNodeTree = (nodes: BoneNode[], parentKey = '0'): ExtendedDataNode[] => {
  return nodes.map((node, index) => {
    const nodeKey = `${parentKey}-${index}`;
    const nodeId = node.id.replace('node_', ''); // 去掉node_前缀
    
    const nodeTreeNode: ExtendedDataNode = {
      key: nodeKey,
      title: <span>...</span>,
      data: { 
        path: iotBindingAPI.buildTargetPath(TargetType.NODE, nodeId),
        value: node, 
        type: 'node'
      },
      children: [
        {
          data: { 
            path: iotBindingAPI.buildTargetPath(TargetType.NODE, nodeId, 'translation'),
            value: node.translation,
            type: 'array'
          }
        },
        // rotation 和 scale 类似
      ]
    };

    // 递归处理子节点
    if (node.children && node.children.length > 0) {
      const childNodes = buildNodeTree(node.children, nodeKey);
      nodeTreeNode.children = [...(nodeTreeNode.children || []), ...childNodes];
    }

    return nodeTreeNode;
  });
};
```

#### 2.3 路径格式

**节点路径格式**：
- 节点本身：`node.{nodeId}`
- 节点属性：`node.{nodeId}.{property}`

**示例**：
- `node.1.translation`
- `node.1.rotation`
- `node.1.scale`

#### 3.2 树结构构建

**函数**：`buildMaterialTree()` (第 1904-2022 行)

**构建逻辑**：
1. **材质路径**：`material.{materialId}.{property}`
   - `materialId` 是从 `material.id` 中去掉 `material_` 前缀得到的
   - 例如：`material.material_0` → `material.0`

2. **材质属性**：包括材质的所有属性
   - 基础属性：`baseColorFactor`、`metallicFactor`、`roughnessFactor` 等
   - 纹理属性：`textures.{textureKey}`

3. **递归处理**：对于嵌套对象，递归构建子节点

**路径示例**：
```
material
├── 0
│   ├── baseColorFactor
│   ├── metallicFactor
│   ├── roughnessFactor
│   └── textures
│       └── baseColorTexture
└── 1
    ├── baseColorFactor
    └── ...
```

**代码实现**：
```typescript

  const realMaterials = getMaterialsFromCesiumModel();
  const materialsToUse = realMaterials.length > 0 ? realMaterials : [/* 示例数据 */];

  return materialsToUse.map((material, index) => {
    const materialId = material.id.replace('material_', '');
    
    const materialNode: ExtendedDataNode = {
      key: `material-${index}`,
      title: <span>...</span>,
      data: { 
        path: iotBindingAPI.buildTargetPath(TargetType.MATERIAL, materialId),
        value: material, 
        type: 'material'
      },

        // 材质属性
        ...Object.keys(material.properties).map((propKey) => ({
          data: { 
            path: iotBindingAPI.buildTargetPath(TargetType.MATERIAL, materialId, propKey),
            value: propValue,
            type: typeof propValue
          }
        })),
        // 纹理信息
        ...Object.keys(material.textures || {}).map((textureKey) => ({
          data: { 
            path: iotBindingAPI.buildTargetPath(TargetType.MATERIAL, materialId, `textures.${textureKey}`),
            value: textureValue,
            type: 'texture'
          }
        }))
      ]
    };

    return materialNode;
  });
};
```

#### 3.3 路径格式

**材质路径格式**：
- 材质本身：`material.{materialId}`
- 材质属性：`material.{materialId}.{property}`
- 纹理属性：`material.{materialId}.textures.{textureKey}`

**示例**：
- `material.0.baseColorFactor`
- `material.0.metallicFactor`
- `material.0.textures.baseColorTexture`

## 路径格式总结

### 三种目标类型的路径格式

| 类型 | 格式 | 示例 |
|------|------|------|
| **实例属性** | `instance.{property}.{key}` | `instance.instance.properties.temperature` |
| **模型节点** | `node.{nodeId}.{property}` | `node.1.translation` |
| **材质属性** | `material.{materialId}.{property}` | `material.0.baseColorFactor` |

### 路径构建规则

1. **根级别**：使用 `buildTargetPath(TargetType, id)` 构建
2. **嵌套级别**：使用点号连接：`{parentPath}.{childKey}`
3. **ID 处理**：
   - 节点ID：去掉 `node_` 前缀
   - 材质ID：去掉 `material_` 前缀
   - 实例属性：直接使用属性名

## 注意事项

1. **实例属性数据**：
   - 数据来自后端 API `GET /instances/{instance_id}/properties`
   - 返回的数据包含 `asset`、`instance`、`bindings` 三个分组
   - `buildPropertyTree` 会遍历整个数据结构，构建完整的树形结构

2. **模型节点数据**：
   - 数据来自动画系统（`animationState.boneNodes`）
   - 需要模型已加载并包含动画节点信息
   - 如果数据不可用，节点列表为空并显示提示信息

3. **材质属性数据**：
   - 数据从 Cesium 模型中实时提取
   - 如果无法获取真实材质，会使用示例材质数据
   - 真实材质显示绿色标签「真实材质」，示例材质显示灰色标签「示例材质」

4. **路径格式**：
   - 必须遵循 `{type}.{id}.{property}` 格式
   - 路径中的 ID 会自动处理前缀（如 `node_`、`material_`）
   - 嵌套属性使用点号连接

5. **表单更新**：
   - 使用 `form.setFieldValue` 更新特定字段
   - 避免触发整个表单的重新渲染
   - 路径会直接回填到 `bindings[bindingIndex].target` 字段

6. **数据刷新**：
   - 每个标签页都有「刷新」按钮
   - 实例属性：重新调用 API 获取最新数据
   - 模型节点：节点数据来自动画系统，刷新需要重新加载模型
   - 材质属性：重新从 Cesium 模型中提取

## 总结

「选择目标属性」功能通过可视化界面简化了 IoT 绑定配置过程，用户无需手动输入路径字符串，只需在树形结构中选择即可。系统支持三种类型的目标属性：

1. **实例属性**：从后端 API 获取，支持完整的实例数据结构
2. **模型节点**：从动画系统获取，支持节点的变换属性
3. **材质属性**：从 Cesium 模型提取，支持材质的所有属性

每种类型都有对应的数据来源、树结构构建逻辑和路径格式规范，确保了功能的完整性和易用性。
